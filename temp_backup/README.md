# Kiki Courier — PHP CLI Solution

A command‑line implementation of the **Courier Service** challenge (Everest Engineering).  
It calculates **delivery cost & discounts** (Problem 1) and **estimated delivery times** (Problem 2) with a multi‑vehicle scheduler that follows the SRS tie‑break rules.

---

### What lives where (quick guide)

- **`main.php`**
  Parses input, validates it, wires up offers, runs the cost calculator and (optionally) the scheduler, and prints output in the exact format the SRS expects.

- **`src/Domain/*`**
  Lightweight models representing core entities:

  - `Package` (id, weight, distance, offer code)
  - `Vehicle` (id, speed, capacity, availability timestamp)
  - `Shipment` (if used) — a bundle of packages dispatched together

- **`src/Offers/*`**
  Extensible offer system:

  - `RangeOffer` implements distance/weight criteria and percentage discount.
  - `NoOffer` handles unknown/NA codes.
  - `OfferRegistry` decides which offer applies.

- **`src/Services/*`**
  The “brains”:

  - `CostCalculator` applies the pricing formula and discounts.
  - `DeliveryScheduler` builds optimal shipments (capacity-constrained), applies tie-break rules (max count → heavier total → earlier finish), and computes ETAs with **two-decimal truncation at each step**.

- **`src/Support/*`**
  Helpers that keep services clean:

  - `Combinatorics::allSubsets()` to generate feasible shipments.
  - `MinHeap` for choosing the next available vehicle.

- **`tests/`**
  Black-box PHPUnit tests that pipe fixtures into `main.php`.
  They assert the official SRS timeline (`3.98 / 1.78 / 1.42 / 0.85 / 4.19`), a second scenario, and pricing/discount behavior (including invalid code).

- **`composer.json` / `phpunit.xml.dist`**
  Composer metadata and PHPUnit configuration.
  (Optional scripts: `"test"`, `"analyse"`, `"cs"`, `"cs:fix"`.)

- **`vendor/`**
  Composer-managed dependencies and autoloader (generated by `composer install`).

### Where to change what

- **Add a new offer code** → `src/Offers/RangeOffer.php` (or create a new rule) and register it in `main.php` via `OfferRegistry`.
- **Adjust vehicle rules or tie-breaks** → `src/Services/DeliveryScheduler.php`.
- **Modify pricing** → `src/Services/CostCalculator.php`.
- **Add more scenarios** → create new pairs in `tests/fixtures/` and add a test or reuse existing test classes.

## 5) Inputs & Offers (per SRS)

**Input format**

```
<base_delivery_cost> <no_of_packages>
<pkg_id> <pkg_weight_kg> <distance_km> <offer_code>
...
[OPTIONAL for ETA]
<number_of_vehicles> <max_speed_kmph> <max_carriable_weight_kg>
```

**Cost formula**: `base + (10 × weight_kg) + (5 × distance_km)`

**Offer codes** (applied only when criteria match; otherwise discount is 0):

- `OFR001`: distance `< 200` AND weight `70–200` → **10%**
- `OFR002`: distance `50–150` AND weight `100–250` → **7%**
- `OFR003`: distance `50–250` AND weight `10–150` → **5%**
- `NA` or unknown codes → **0%**

---

## 6) Scheduling & Time Rules (Problem 2)

- All vehicles share the same **speed** and **capacity** (from the last input line).
- For each dispatch, we choose the shipment by SRS tie‑breaks:
  1. **Maximize package count**
  2. If tie, **maximize total weight**
  3. If tie, **earlier finish** (smaller farthest distance)
- One-way time per package: `distance / speed`
- A vehicle becomes available again after a **round trip** to the farthest package in its dispatch.
- **Two‑decimal truncation at every step** (one‑way, arrival, round‑trip/availability), not rounding.

## 8) Troubleshooting

- **`php` is not recognized** (Windows): Install PHP and add it to PATH; restart the terminal.
- **Composer not found**: Install from https://getcomposer.org/ .
- **Malformed input**: The CLI validates inputs and prints a friendly error with exit code `1`.
- **A package exceeds capacity**: The CLI will report the offending package id and exit.

## 9) Design Notes (overview)

- **SOLID & separation of concerns**: Domain (`Package`, `Shipment`, `Vehicle`), services (`CostCalculator`, `DeliveryScheduler`), and offers (`OfferRegistry` + `RangeOffer`/`NoOffer`).
- **Extensibility**: New offers can be added without changing calculator logic (Open/Closed).
- **Deterministic math**: Truncation to two decimals on all time computations to mirror SRS examples exactly.
- **Complexity**: Shipment selection enumerates feasible subsets under capacity, ensuring correct SRS tie‑breaks for challenge‑scale inputs.
